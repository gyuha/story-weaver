# Work 목록·생성만 먼저 실 API로 전환, 하위 도메인(챕터·엔티티·타임라인·링크)은 계속 로컬 mock 유지

World Bible 백엔드(엔티티 카드·타임라인 상태·씬-엔티티 링크·계층)를 한 번에 만들려 했으나, 이미 백엔드에 존재하는 Work 최상위 API조차 웹에 연동되어 있지 않다는 사실이 확인됐다(`works.api.ts` 파사드는 있으나 아무 컴포넌트도 쓰지 않음). 하위 도메인(챕터·씬·엔티티·타임라인·충돌)은 엔티티가 참조할 실제 `work_id`가 있어야 의미가 있으므로, **Work 목록/생성부터 실 API로 전환하고 하위 도메인은 각자 백엔드가 생길 때까지 계속 클라이언트 로컬 상태(빈 배열로 시작, 세션 내 편집)로 남긴다.**

이 결정으로 기존 데모 시드(챕터·씬·엔티티·타임라인이 채워진 mock 예시 작품)는 제거되고, 새로 만드는 실 작품은 하위 도메인이 빈 상태로 시작한다(기존 mock `addWork`와 동일 동작이라 회귀는 아님). World Bible/에디터/타임라인 화면은 각 하위 도메인 백엔드가 생기기 전까지 로컬 편집만 가능하고 새로고침 시 유지되지 않는다 — 이는 로드맵(M1) 의존 순서(Work → 계층 → 엔티티 → 상태/링크)를 그대로 따르는 의도된 중간 상태다.
