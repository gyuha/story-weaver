# 캐릭터 일관성은 비전 역번역 [[시각 묘사]]로 확보하고, 그 묘사는 `attributes` 밖에 둔다

`image-generation.md` 2.1은 캐릭터 일관성의 후보를 셋 제시한다 — (a) 레퍼런스 + IP-Adapter/LoRA, (b) 시드 고정 + 프롬프트 템플릿, (c) 상용 API의 캐릭터 참조. 그런데 ADR `260811-234511`의 실측대로 우리 게이트웨이는 **레퍼런스 이미지 입력(`images/edits`)을 지원하지 않고, `seed`를 받지만 무효**다. (a)는 자체 GPU가 필요하고 ADR-0003이 피한 비용 구조다. **즉 셋 중 어느 것도 그대로 쓸 수 없고, 통제 가능한 입력은 프롬프트 텍스트 하나뿐이다.** 그래서 (b)를 시드 없이 밀어붙인다: 생성 직후 그 이미지를 **비전 모델에 되먹여 상세 외형 서술을 뽑고**, 그것을 [[시각 묘사]]로 카드에 축적해 다음 재생성의 입력으로 쓴다. 그리고 그 묘사는 엔티티 `attributes`가 아니라 이미지 행(`entity_images`)에 저장하며, 카드의 현재 시각 묘사는 [[대표 이미지]]의 묘사로 정의한다.

## Considered Options

- **생성 레시피(템플릿 ID + 최종 프롬프트)만 저장** — 거의 공짜다. 그러나 `revised_prompt`가 입력을 그대로 에코하므로(실측) 저장되는 "자세한 설명"이 결국 작가가 이미 카드에 쓴 `외모` 필드와 같은 문장이다. 재생성 결과는 그대로 흔들린다.
- **묘사를 엔티티 `attributes`에 넣고 임베딩 조립에서 제외** — 카드 한 곳에 모이는 이점이 있으나 `_entity_content()`를 고쳐야 하고(기존 카드 전부 재임베딩), 나중에 누가 키를 하나 더 넣으면 제외 규칙을 다시 새는 구조다. 방어가 규율에 의존한다.
- **엔티티에 `visual_description` 전용 컬럼** — 오염은 없으나 이미지를 append-only로 쌓기로 한 것과 어긋난다. "이 묘사는 어느 이미지의 것이냐"가 모호해지고 대표를 바꿀 때 수동 동기화가 생긴다.

## Consequences

- **"같은 얼굴 보장"은 하지 못한다.** 상세 프롬프트 재사용은 비슷한 인상까지이고, 설정집의 "항상 이 모습"은 이 인프라로 달성 불가다. UI가 이것을 보장처럼 보이게 하면 안 된다. 레퍼런스 참조를 지원하는 제공사로 옮기는 것이 이 한계를 실제로 없애는 유일한 길이다.
- **`attributes`에 묘사를 넣지 않는 것이 이 결정의 절반이다.** `worldbible_service.py`의 `_entity_content()`는 `attributes` JSONB **전체**를 `json.dumps`해 임베딩 텍스트로 쓰고, `memory_service.index_source`는 "엔티티 카드는 짧아" `chunk_index=0` 하나만 쓴다. 1,500자 시각 묘사를 `attributes`에 넣으면 집필 중 [[메모리]]가 "아랫입술은 살구분홍색" 같은 문장을 컨텍스트로 물어오고, 카드의 진짜 설정이 한 벡터 안에서 희석된다. `entity_images`에 두면 이 오염이 **구조적으로 불가능**해지고 기존 임베딩 조립 코드를 건드리지 않는다.
- 비전 호출이 생성마다 한 번 더 붙어 총 소요가 최대 2분이 된다. 그래서 **이미지를 먼저 커밋하고 묘사를 뒤에 채운다** — 묘사 단계에서 취소·오류가 나도 이미지는 남는다(`visual_description = null`). null인 행은 재생성 입력으로 쓰지 않으며, 다시 만들려면 그냥 재생성한다(묘사 전용 재시도 버튼을 두지 않는다).
- 두 호출(이미지 생성·비전 묘사) 모두 `llm_calls`에 `task="image_generation"` / `"image_description"`으로 기록한다(ADR-0009). 이미지 생성은 `ChatLiteLLM`을 타지 않으므로 로깅이 자동으로 붙지 않고 직접 붙여야 한다.
- 카드의 시각 묘사가 대표 이미지의 파생값이므로, 대표를 바꾸면 묘사도 따라 바뀐다. 작가가 묘사를 고치면 그것은 **그 이미지 행의** 묘사를 고치는 것이다.
