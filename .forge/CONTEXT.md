# StoryWeaver

AI가 작가의 세계관·캐릭터·설정을 기억하고 집필을 보조하는 웹 기반 웹소설 창작 SaaS의 도메인 용어집.

## Language

**작품 (Work)**:
한 명의 작가가 집필하는 하나의 소설 프로젝트. 모든 설정·플롯·원고의 최상위 소유 단위.
_Avoid_: 프로젝트, 책, 소설(파일)

**World Bible**:
한 작품의 모든 설정(인물·장소·사건·아이템 등)을 저장·관리하는 설정 저장소. "기억하는 AI"의 근거 데이터.
_Avoid_: 설정집, 위키, 노트

**엔티티 카드 (Entity Card)**:
World Bible 안의 한 항목(인물·장소·사건·아이템 중 하나)을 표현하는 정형 데이터 단위. 정해진 필드(이름·속성 등)를 가진다.
_Avoid_: 설정 항목, 노드, 문서

**타임라인 상태 (Timeline State)**:
한 엔티티가 특정 시점(**화**)에 갖는 상태. "3화에서 사망", "5화에서 각성"처럼 시간에 따라 변하는 사실을 기록해 상태 추적과 설정 충돌 감지의 근거가 된다. 시점 축은 화 단위 `global_seq`이며, 시점 쿼리는 `up_to_chapter_id`다(구 `up_to_scene_id`에서 화 단위로 뭉툭해짐).
_Avoid_: 히스토리, 로그, 변경 이력

**씬 (Scene)** — [폐지]:
집필·AI 생성의 최소 단위였으나 **폐지**됨. 화(=챕터)가 본문(`body`)을 직접 보유하는 최소 단위로 흡수했다(ADR 260716-17a). 계층에서 씬 말단이 사라져 `작품 → 부 → 화`가 됐다. 코드/DB의 `SceneEntityLink`/`scene_entity_links` 등 일부 식별자는 의도적으로 이름만 유지(→ [[화-엔티티 링크]]).
_Avoid_: 더 이상 도메인 계층이 아님 — 신규 문구에서 집필 단위로 "씬"을 쓰지 말 것(화를 쓴다).

**시놉시스 (Synopsis)**:
작품의 **제목**과 **기획의도**로 구성되는 작품 소개. 등장인물 소개는 [[World Bible]]이, 줄거리는 별도 영역(검토·타임라인 확장 후보)이 다룬다. `작품 → 부 → 화(=챕터)` 계층의 한 단계가 아니라 작품 직속.
_Avoid_: 줄거리 요약, 로그라인, 비트 시트, 카드(retired ADR-0011)

**화-엔티티 링크 (Chapter-Entity Link)**:
특정 **화**에 어떤 엔티티가 등장하는지를 명시하는 연결. [[메모리]]가 무엇을 불러올지 정하는 1차 근거(벡터 유사도는 보조). `UNIQUE(chapter_id, entity_id)`. 코드/DB 식별자는 `SceneEntityLink`/`scene_entity_links`를 그대로 유지한다(리네임 비용 회피 — `episode`/`write` 선례와 동일).
_Avoid_: 씬-엔티티 링크(사용자 대면), 태그, 참조

**메모리 (Memory)**:
현재 집필 중인 **화 본문**과 관련된 World Bible 설정을 찾아 AI에게 컨텍스트로 제공하는 작업·그 결과. 정형 카드 + 벡터 검색(**화 본문을 문단 그룹핑 ~800자로 청킹한 임베딩** `chunk_index 0..N-1`) + [[화-엔티티 링크]]의 하이브리드로 구성된다(ADR-0002를 ADR 260716-17a가 개정: 씬 단위 → 화 단위). 검색은 자기 화를 제외한다.
_Avoid_: RAG(사용자 대면 UI·문구에서는 '메모리'; 내부 설계 문서는 RAG 사용 가능), 컨텍스트 주입

**채팅 (Chat)**:
집필 화면 우측 패널에서 작품에 대해 자유롭게 묻고 답하는 기능. 대화는 **작품 단위**로 이어진다(화를 옮겨도 유지). 매 턴 현재 화 원고 전문 + [[메모리]] 검색 결과로 컨텍스트를 새로 조립해 최신 집필 내용을 반영한다(고정 시스템 프롬프트가 아님). "새 대화 시작"으로 리셋 가능.
_Avoid_: Q&A, 상담 (코드 식별자는 chat 유지)

**모델 스위칭 (Model Switching)**:
집필 작업의 종류(이어쓰기·교정·구조 생성 등)에 따라 저비용/고품질 LLM을 골라 호출하는 전략.
_Avoid_: 모델 라우팅, 폴백

**품질 티어 (Quality Tier)**:
사용자가 설정 화면에서 작품 전체에 적용하는 생성 품질 수준(저비용/균형/고품질). [[모델 스위칭]]이 이 티어를 기준으로 삼아 작업별 모델을 자동 선택한다. 사용자는 구체 모델명·API 키를 직접 다루지 않는다(BYOK 아님 — 키는 서버가 보유).
_Avoid_: 플랜, 등급, 모델 선택, BYOK

**읽기 모드 (Reading Mode)**:
작가가 자신의 원고를 독자처럼 연속으로 읽는 read-only 검토 뷰. AI·메모리·작업 크롬을 걷어내고 **화 단위 본문**만 보여준다(화가 본문을 직접 보유하므로 다중 씬 concat 없이 단일 렌더). **편집 모드**와 짝을 이루는 별개 모드이며, 외부 독자용 퍼블리싱이 아니라 작가 본인의 흐름·오탈자 점검 용도다.
_Avoid_: 미리보기, 독자 뷰, 뷰어

**편집 모드 (Edit Mode)**:
원고를 작성·수정하는 집필 화면(`write`). **화 1개 단위**로 AI 이어쓰기·메모리 패널·작업트리를 함께 제공한다. 라우트는 `write/$chapterId`. [[읽기 모드]]와 대비되는 짝.
_Avoid_: 작성 모드 (코드 식별자는 `write`/'집필' 유지)

**AI 이어쓰기 (Continue)**:
[[편집 모드]]에서 커서 직전 본문을 근거로 AI가 **여러 갈래의 다음 전개 후보**를 제시하고, 작가가 그중 하나를 골라 본문에 삽입하는 집필 보조. 후보는 서로 다른 전개여야 하며 [[메모리]] 컨텍스트의 설정과 모순되면 안 된다. 작가가 고르기 전까지 원고는 바뀌지 않는다 — AI가 이어 쓰는 것이 아니라 **작가가 후보를 채택**하는 구조다. 코드/API 식별자는 `continue`(assist 태스크의 하나)를 유지한다.
_Avoid_: 자동 완성, 자동 생성, 오토 라이팅 (AI가 원고를 대신 쓴다는 함의를 피한다)

**부 (Part)**:
한 작품을 큰 서사 단위로 나눈 묶음(예: 제1부 청운문편). `작품 → 부 → 화(=챕터)` 계층에서 작품 바로 아래 단계다. `docs/data-model.md`가 정본 계층에서 **에피소드(Episode)**로 부르던 자리이며, 사용자 대면 명칭을 "부"로 통일한다(코드/DB 식별자 `episode*`는 유지). web 코드에서는 각 화에 박힌 자유 문자열 `partLabel`로 표현된다.
_Avoid_: 에피소드(사용자 대면), 편, 장, 시즌

**화 (= 챕터 / Chapter)**:
부 안의 한 회차이자 **집필·AI 생성의 최소 단위**. 본문(`body`)과 작품 전역 순서축(`global_seq`)을 직접 보유한다. 사용자 대면 명칭은 "N화"(예: 6화), 코드/도메인 식별자는 `Chapter`이며 `index`가 화 번호다.
_Avoid_: 회차(코드), 에피소드, 씬(하위 계층 없음)

**버전 기록 (Version History)**:
한 **화(챕터)**의 본문이 **작가의 집필 시간축**을 따라 저장돼 온 스냅샷들의 기록. 시간대별로 과거 버전을 읽고, 현재 버전으로 덮어쓰며(현재로 보내기), 변경분을 비교할 수 있다. 편집은 현재 버전만, 과거 버전은 읽기 전용. **타임라인 상태와 다른 축이다** — 타임라인 상태는 엔티티가 *작중 시점*에 갖는 상태이고, 버전 기록은 *원고가 실제로 고쳐져 온 이력*이다.
_Avoid_: 히스토리, 타임라인(타임라인 상태와 혼동 금지), 리비전

**관리자 (Admin)**:
서비스 운영자 역할(role `ADMIN`). [[계정 승인]]과 운영 통계 조회 권한을 가지며, 작품을 소유·집필하는 **작가**와 구분되는 별개 역할이다. 한 계정이 둘을 겸할 수 있으나 개념은 분리한다.
_Avoid_: 슈퍼유저, 운영자(코드 식별자), 매니저

**계정 승인 (Account Approval)** — [미구현]:
회원 가입한 계정에 [[관리자]]가 서비스 사용 허가를 부여하는 절차. 초기 테스트 기간 동안 승인된 계정만 서비스를 쓸 수 있게 하는 게이팅 수단으로 **의도된** 개념이다. 계정 상태는 `대기(pending) → 승인(approved)` 또는 `거부(rejected)`로 전이한다. (이메일 인증·정지와 다른 축 — 이메일 인증은 본인 확인, 승인은 운영자 허가다.)
**현재 이 게이트는 존재하지 않는다** — 백엔드 `User`에는 `is_active`(정지/soft-delete) 불리언만 있고 승인 상태 필드가 없으며, 승인·거부 엔드포인트도 없다(`admin_ops.py`는 CLI 전용이고 계정 승인을 다루지 않는다). web `features/admin`의 승인 화면은 로컬 목업 스토어로 동작한다. 즉 **이메일 인증만 통과하면 누구나 서비스를 쓴다.** 이 항목을 근거로 "승인 게이트가 접근을 막고 있다"고 가정해선 안 된다.
_Avoid_: 가입 승인, 활성화, 인증(이메일 인증과 혼동 금지)

**회원 (Member)**:
가입한 한 계정을 [[관리자]] 관점에서 부르는 말 — 승인 대상 목록·통계의 단위. 집필 맥락의 "작가"와 같은 사람을 가리키되, 관리 화면에서는 작품 소유자가 아니라 *승인·집계 대상 계정*으로 본다.
_Avoid_: 유저, 가입자

**사용량 한도 (Usage Limit)**:
한 사용자가 일정 주기 안에 쓸 수 있는 AI 생성량의 상한. 도달하면 생성 요청이 막히고 사용자는 "이번 주기 사용량 한도 도달"을 본다. 사용자는 모델·API 키를 직접 다루지 않으므로([[품질 티어]]) 이것이 사용자가 체감하는 유일한 생성량 통제 장치다. 세는 단위는 **전달받은 분량**이다 — [[AI 이어쓰기]]를 중간에 취소해도 그때까지 받은 만큼은 한도에 잡힌다(취소가 무료는 아니다).
_Avoid_: 쿼터, 크레딧, 요금(과금과 다르다 — 이건 사용량 상한이다), 토큰 수(사용자 대면 문구에서 "토큰"을 쓰지 않는다)

**화 요약 (Chapter Summary)**:
한 [[화]]에서 무슨 일이 일어났는지를 2~3문장으로 적은 서술. 작가가 직접 쓰거나 AI가 본문을 근거로 지어 주며, [[검토 · 타임라인]] 화면이 화 순서대로 모아 작품 전체 흐름을 한눈에 보여준다. [[타임라인 상태]](엔티티의 시점별 키-값 사실)와 다르고, 엔티티 카드의 한 줄 요약(임베딩 대상)과도 다르다 — 셋이 같은 화면·비슷한 말을 쓰므로 구분해야 한다. 화 요약은 임베딩하지 않는다.
_Avoid_: 시놉시스(작품 단위다), 개요, 로그라인, 줄거리(구어로는 쓰지만 코드·UI 라벨은 "요약")

**늘려쓰기 (Draft from Summary)**:
[[화 요약]]을 근거로 AI가 그 화의 **본문 자체를 써 주는** 작업. [[AI 이어쓰기]]와 방향이 반대다 — 이어쓰기는 본문을 근거로 다음 전개 후보를 내고 작가가 채택하지만, 늘려쓰기는 요약을 근거로 원고를 생성해 본문에 반영한다. 그래서 기존 원고를 지울 수 있고, 본문이 이미 있으면 대체 여부를 작가에게 확인해야 한다. 근거에 [[메모리]] 전체를 주입한다 — 인물·설정을 모르고 쓰면 이 제품의 전제가 무너진다. **UI 레이블은 `요약으로 본문 작성`** — 화면에서는 무엇을 근거로 무엇을 만드는지 그대로 드러내고, 팀·코드·문서에서는 이 용어를 쓴다([[메모리]]가 내부 개념이고 화면 문구는 따로인 것과 같은 분리).
_Avoid_: 이어쓰기(방향이 반대다), 자동 집필, 초고 생성(작품 전체를 쓴다는 함의를 피한다)
