## Learnings

**1. "기존 방어 장치 안에서의 변경"은 실측 면제 사유가 아니다.**
계획은 "S1은 #65가 이미 깐 `anyio.CancelScope(shield=True)` 안에서 값만 고르므로 새 실스택 테스트가 필요 없다"고 판단했다. 그 추론이 무효인 이유: **방어 장치가 있다는 것과 새 코드가 그 안에서 발동한다는 것은 다른 명제다.** shield는 `await`을 살려주지만, `except asyncio.CancelledError`의 플래그가 실제로 세워지는지는 별개다. 내가 가진 증거는 ① 합성 제너레이터 프로브 ② 평범한 `task.cancel()` 단위 테스트뿐이었고 둘 다 **운영 제너레이터가 실제 anyio 취소에서** 어떻게 되는지는 증명하지 않는다.
결과적으로 추가한 테스트는 green이었고 플래그를 제거하니 red가 됐다(단위 테스트도 red — 플래그 대입이 sync라서). **즉 면제해도 결과는 같았을 수 있지만, 그걸 사전에 알 방법이 없었다는 것이 요점이다.**
→ **다음에**: 취소·타임아웃·비동기 스코프가 걸린 코드는 "이미 방어가 있으니까"를 근거로 실스택 증명을 생략하지 않는다. 훅 5번 항목으로 다록했다.

**2. UAT 지시에는 화면 경로와 코드에서 읽은 정확한 레이블을 인용해야 한다.**
"메모리 패널의 챗 탭"이라고 썼는데 실제 레이블은 `채팅`(`memory-panel.tsx:67`)이고 위치는 **집필 화면 오른쪽 패널**(`editor-screen.tsx:17`)이다. 사용자는 편집기 `AI 이어쓰기`를 테스트했고(`llm_call_logs`의 `assist.continue`가 증거) UAT 한 라운드가 버려졌다. **레이블을 코드에서 읽어놓고 인용하지 않은 것**이 원인이다.
→ **다음에**: UAT 지시에 `화면 → 패널 → 정확한 레이블` 경로를 쓴다. 훅 4번 항목으로 다록했다.

**3. 타이밍 의존 DoD 항목은 브라우저 UAT로 관측하려 하면 안 된다.**
`resp_len=0`(첫 토큰 도착 전 취소)이면 `if collected_chunks:` 가드가 저장을 건너뛴다 — 정상 동작이다. 그 때문에 **두 사이클 연속** 운영에서 목표 행을 못 봤다: #65는 non-empty 부분 응답, #66은 `finish_reason='cancelled'` 메시지. 두 번 다 사용자에게 재시도를 요청해 클릭을 소비했다.
→ **다음에**: DoD를 쓸 때 각 항목이 **사람이 확실히 볼 수 있는가**를 판정하고, 타이밍에 걸린 항목은 처음부터 테스트로 고정한 뒤 UAT 목록에서 뺀다.

**4. #65 회고가 만든 훅이 이틀째에 회수됐다.**
`PostToolUse` 훅이 이번 사이클에 **두 번** 작동했다: ① 계획서의 틀린 주장을 잡았다 — "`editor/` 밖에서 `.stop()`을 호출하는 곳은 없다"고 썼는데 #65가 직접 추가한 `synopsis-editor.tsx:140`이 반례였고, 프로덕션 호출부는 2곳이 아니라 5곳이었다(같은 과소열거 실수의 **다섯 번째**, 처음으로 사람이 아니라 훅이 잡음). ② run.md의 미측정 지점을 지적해 실스택 테스트를 추가하게 만들었다.
→ 훅의 값이 확인됐으므로 이번 회고의 학습 1·2를 항목 5·4로 다록했다. 노이즈가 되면 `.claude/settings.local.json`에서 제거한다.

**5. LSP 진단이 세 번 즉시 잡았다**(타입 2건 + import 1건). 왕복이 짧아졌다. 승급할 학습은 아니다.
