## 발산

1. **데이터 유실 경로 리뷰가 실제 결함 3건을 잡았다 — 전부 완성 기준이 보지 않는 축이었다.**
   계획의 S4 완성 기준 4항목(선저장→복원 순서 / 선저장 실패 시 중단 / 미저장 없을 때 1회 / invalidate)은 **정확히 검증되어 있고 실제로 옳게 동작한다.** 리뷰가 찾은 것은 그 넷이 다루지 않는 **동시성·재진입·거짓양성** 축이다.
   - **[critical] 되돌리기 중 화를 떠나면 복원이 조용히 무효화된다.** 되돌리기 클릭 직후 다른 화를 클릭하면 언마운트 자동 저장이 **독립적인 fire-and-forget PATCH**를 추가로 쏜다(총 3회: 선저장·orphan·복원). `restoreVersion`은 자기 선저장만 await하고 orphan의 존재를 모른다. 리뷰어가 deferred promise로 orphan을 가장 늦게 resolve시켜 `setChapterParagraphs`의 마지막 호출값이 복원된 옛 본문이 아니라 **복원 전 편집 텍스트로 되돌아가는 것**을 재현했다. 백엔드도 낙관적 동시성 제어가 없어(`setattr` 후 그대로 commit) 같은 last-write-wins가 서버에도 성립한다 — **성공 토스트가 뜬 뒤 서버 상태가 조용히 되돌아갈 수 있었다.** 수정: `restoringRef` 잠금을 언마운트 정리 effect와 공유. 실패 시엔 잠금을 풀어 원래 자동 저장이 살아나게 남겼다(편집분 유실 방지가 이 기능의 존재 이유).
   - **[high] 미저장 판정이 공백 정규화로 거짓양성을 낸다.** TipTap/ProseMirror가 문단 앞뒤 공백을 트림하고 내부 연속 공백을 하나로 축약하며 문단 내 리터럴 개행을 공백으로 합친다(실 TipTap v3.27.1로 실측). `toParagraphs`는 빈 줄만 걸러 원본 공백을 보존하므로, **마침표 뒤 이중 공백이나 들여쓰기 같은 실제 집필 관행이 있으면 아무 편집 없이 되돌리기만 눌러도** 선저장이 발동해 원본 서식을 영구 손상시킨다. 수정: `initialBodyRef`의 시드를 raw `paragraphs.join('\n')`에서 **에디터가 파싱한 결과**(`editor.getText({blockSeparator:'\n'})`)로 교체.
   - **[medium] 되돌리기 버튼에 진행 중 가드가 없어 더블클릭이 재진입한다**(PATCH 4회). 수정: 함수 레벨 재진입 가드(`restoringRef`) + 버튼 `disabled={restoring}`. 리뷰는 버튼 disabled만 지적했지만 리뷰의 재현이 `onRestore` 직접 호출이라 버튼 가드만으로는 못 막아 둘 다 넣었다.
   세 수정 모두 **회귀 테스트를 먼저 써서 red를 확인하고, 방어를 무력화해 그 테스트만 단독 실패하는 것까지 확인**했다(각 `expected 1, got 2`, 나머지 53개 통과). `grep -n TEMP-RED-CHECK` 0건 확인.
2. **`initialBody` → ref 전환이 계획 범위를 넘어 `saveChapter`까지 건드렸다.** ref로 바꾸면 수동 저장 후에도 같은 중복-PATCH 리스크가 **새로 생기므로** 필수 후속 조치였다. 계획의 "확인 필요"가 남긴 재임베딩 헛돎을 해소한 것이지만, 계획에 없던 확장인 것은 사실이다.
3. **`더 보기`가 진짜 페이지네이션이 아니다.** limit을 30씩 키워 offset 0부터 전량 재요청한다 — 코드는 가장 짧지만 항목이 100을 넘으면 더 못 받는다(API 상한). `// eco:` 주석에 상한과 업그레이드 경로를 적었다. 상한 없는 보존을 정했으므로 **버전이 100개를 넘는 화가 나오면 이건 실제로 막힌다** — 후속 과제.
4. **playwriter MCP가 이 세션 툴셋에 없다** — 구현 B·C·수정 에이전트가 모두 `ToolSearch`로 확인했고 메인 세션에서도 없음을 확인했다. 계획 DoD의 `playwriter로 위 흐름 육안 확인`을 **수행하지 못했다.** 자세한 것은 아래 "검증 상태".
5. **리뷰어가 `git checkout --`을 잘못 실행했다.** 리뷰 대상이던 미저장 테스트 파일을 일시 삭제했고, 세션 초반 `Read` 캡처로 복구했다고 보고했다. 게이트가 전부 통과하고 테스트 수 추이가 일치하므로 실질 손실은 없어 보이지만, **복구가 바이트 단위로 동일함을 증명한 것은 아니다** — 잔여 리스크로 기록한다.
6. **되돌리기 성공 후 모달을 닫지 않는다.** 계획의 4단계 지시에 "닫기"가 없고 DoD의 "목록에 항목이 둘 늘어난다"를 열린 채로 확인하는 그림에 맞아 그렇게 정했다. 기존 목업의 `setShowHistory(false)`를 제거했다. UAT에서 어색하면 바뀔 수 있는 지점이다.
7. **테스트가 `useQueryClient`만 부분 목한다.** 실 `QueryClientProvider`를 새로 씌우는 대신 최소 diff를 택해 기존 20여 개의 `render(<ManuscriptEditor/>)`를 건드리지 않았다. 다만 `../version-history-modal` 목의 캡처 대상에 `onRestore`를 **실 함수 참조로** 넣어, `vi.fn()` 스텁이 아니라 `manuscript.tsx`의 진짜 async 함수가 호출된다 — 직전 회고가 지적한 "목이 부작용을 재현하지 않으면 실제 경로를 가린다"를 의식한 설계다.
8. **`charDelta` 표시 보정이 필요 없었다.** #72가 서버 `char_count`를 web의 공백 제외 규칙에 미리 맞춰 놨다. 계획 2of2의 "글자 수 규칙 일치" 확인 항목은 손대지 않고 닫혔다.

## 계획 대조 · Non-goals

계획 대조 에이전트 판정 **pass, findings 0** — 4개 슬라이스의 완성 기준을 코드·테스트로 하나씩 대조했다. 확인된 것: 날짜 그룹 테스트가 `vi.useFakeTimers({toFake:['Date']})` + `vi.setSystemTime`으로 시각을 고정해 flaky하지 않다, `charDelta!==null` 방어가 렌더 코드에 실재하고 테스트가 `textContent`로 단언한다, 미저장 행이 목록 루프 밖 별도 엘리먼트라 섞이지 않는다, `더 보기` 45개 케이스에서 `Set(labels).size===45`로 중복 없음을 검증한다, `manuscript.tsx`가 `editor?.getText({blockSeparator:'\n'})`를 넘긴다.

Non-goals 침범 없음: 두 과거 버전 간 비교 UI 없음, side-by-side diff 없음(기존 인라인 단어 diff 유지), 버전 삭제·이름 붙이기 없음, 되돌리기 확인 다이얼로그 없음(기존 `ConfirmDialog`는 "요약으로 본문 쓰기" 전용이고 되돌리기 경로에 붙지 않음), `src/routes/` 무변경(읽기 모드·검토 화면 새 진입점 없음), `src/api/**`·`routeTree.gen.ts` 직접 편집 없음(전량 `pnpm generate` 산출물), `api/` 무변경(git status의 api 변경분은 #72가 이미 봉인한 것).

## 브라우저 UAT — playwriter 없이 수행했다

playwriter MCP가 이 세션에 없어(ToolSearch 2회 확인) 처음엔 `verified: pending`으로 벽을 선언했다. 그러나 **머신에 Python playwright와 chromium이 캐시돼 있었다**(`~/Library/Caches/ms-playwright`에 `chromium-1208/1217/1228`, `mise` python에 playwright 설치). 인증만 넘으면 실제 앱을 볼 수 있었고, 앱 자체의 `create_access_token`을 그대로 호출해 로컬 dev 토큰을 만들어 `localStorage['sw-auth-v3']`에 주입했다(ADR-0007의 저장 방식). **`manage.py reset-password`로 계정 비밀번호를 바꾸는 길은 택하지 않았다** — 스크린샷을 얻으려고 사용자 계정을 건드릴 이유가 없다.

**사용자의 실제 원고는 읽기 전용으로만 열었다.** 모달을 띄워 렌더만 확인하고 타이핑·저장·되돌리기를 하지 않았다(그 셋은 원고를 실제로 바꾼다). 나머지 확인은 **임시 작품**(`ZZ-UAT-임시작품(삭제예정)`)을 만들어 그 안에서만 조작하고 끝나고 삭제했다. 버전 45개는 API PATCH가 아니라 **DB에 직접 삽입**했다 — PATCH마다 `index_chapter`가 돌아 임베딩 비용이 45번 나가고, 지금 보려는 것은 append 로직(이미 테스트로 검증됨)이 아니라 렌더이기 때문이다.

**실 DB에서 확인된 전 흐름** (가장 값이 큰 증거):
```
시드 45개 → 미저장분 타이핑 → 과거 버전 `이 버전으로 되돌리기` 클릭
결과: chapter_versions 47행 (= 45 + 선저장 1 + 복원 1)
  최신-1  "… 최신 저장분. 저장하지 않은 새 문장."   ← 타이핑한 미저장분이 선저장됐다 (유실 없음)
  최신-0  복원된 옛 본문 == chapters.body          ← 불변식 True
```
즉 ADR 260805-214733이 설계한 `미저장분 선저장 → 복사-붙이기 복원 → 이력 보존 → 최신 버전 = 현재 상태`가 실제 DB·실제 UI에서 그대로 성립한다. DoD의 "목록에 항목이 둘 늘어난다"가 이 47행으로 확인됐다.

**계획이 예고한 6개 지점 중 5개 확정:**
- ① `더 보기 (N개 남음)` — 노출되고 항목이 **30 → 45로 누적**되며 중복 없음(`[data-testid=version-item]` 카운트)
- ② `편집 중 · 미저장` — 점선 테두리 + 옅은 노란 배경으로 버전 목록과 구분되어 렌더. 타이핑 후 노출 확인
- ③ 증감 색 — `−6`·`−13`·`−20` 빨강 / `+46`·`+39` 초록, 10px에서도 판독 가능. 마이너스는 U+2212
- ⑤ 시각 병기 — 상대(굵게) + 절대(작게 회색), 날짜 그룹 `오늘`/`어제`/`08-04`. **자정 경계가 실제 데이터에서 맞았다**(현재 01:32 기준 `오늘 00:12` / `어제 23:32`) — 테스트는 가짜 타이머로 본 명제를 라이브로 재확인
- ⑥ `현재 본문은 새 버전으로 보존됩니다` — **`h-14` 좌우 분할에서 줄바꿈 없이 한 줄**. 구현 에이전트가 "코드상으론 판단 불가"로 남긴 항목이 확정됐다

**미확정 1개:** ④ 그룹 헤더 sticky — 스크롤 셀렉터(`div.overflow-y-auto` `.first`)가 좌측 패널을 못 잡아 스크롤이 안 걸렸다. 다만 이것은 **요구사항이 아니라 "UAT에서 결정할 열린 질문"**이다(현재 구현: sticky 아님). 사용자 판단으로 남긴다.

부수 확인: 콘솔 에러 **0건**. 임시 작품 삭제 후 **고아 버전 0** — #72의 `ondelete=CASCADE`가 실제로 동작함을 라이브로 확인. 사용자 작품 `오래살자`의 화 6개는 본문·버전 1개(백필분) 그대로 무변경.

**남는 미검증:** ②③⑤의 *미감* 판단(과한지·읽히는지)은 렌더를 확인했을 뿐 취향은 사용자의 것이다. ④ sticky 결정도 마찬가지. 이 셋은 봉인을 막지 않는 **다듬기 후보**이고, 기능 DoD는 위로 충족됐다.
