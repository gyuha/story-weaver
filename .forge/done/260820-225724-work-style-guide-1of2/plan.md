# 작품에 문체 지침(style_note)을 두고 생성 프롬프트 4곳에 주입한다

## 목표 / 하지 않을 것

- **목표**: 작가가 자기 문체 규칙을 자유 서술로 적을 자리([[문체 지침]])를 작품에 만들고, `work.style`(라벨)이 이미 가는 생성 프롬프트 4곳에 함께 주입한다. 시놉시스 화면에서 읽고 쓴다.
- **하지 않을 것**:
  - **온도 조정** — part 2/2. 이 계획은 프롬프트 내용만 다룬다.
  - `work.style` 3라벨(`간결체`·`만연체`·`서정체`) 폐지나 자유 텍스트화 — 그릴링에서 버렸다(기존 작품·생성 화면·17장르 프리셋을 다 건드리고 되돌리기 어렵다).
  - `genre-presets.json`의 `styleSamples`를 프롬프트에 넣기 — web 전용 데이터이고 내용이 `"그는 검을 들었다. 망설임은 없었다."` 같은 한 문장이라 가이드로 빈약하다. 백엔드가 쓰려면 복제가 필요해 단일 출처가 깨진다.
  - 기존 작품에 기본값 채우기 — null로 남긴다(ADR 260813-110724의 "기본값을 조용히 넣지 않는다").
  - `작품 설정` 메뉴로 화풍+문체를 묶기 — 그릴링에서 버렸다(사용자 대면 메뉴 개명이라 글로서리·테스트·ADR 파급).
  - World Bible에 "금기 사항" 필드 추가 — 조언 ②의 일부이나 이번 범위 밖. 인물 말투는 이미 `speech_style`·`sample_lines`가 있다.

## 참조 근거

- **글로서리**: [[문체 지침]] · [[문체]] · [[작품 화풍]] · [[시놉시스]] (`.forge/CONTEXT.md` — 앞 둘은 이번 그릴링에서 등록했다)
- **관련 ADR**: `260813-110724`(작품이 설정을 소유하는 선례 + "기본값을 조용히 넣지 않는다"), `ADR-0004`(사용자는 모델명·저수준을 직접 다루지 않는다 — 온도를 작가에게 노출하지 않는 근거, part 2/2가 쓴다)
- **새 ADR 없음** — nullable 컬럼 추가와 프롬프트 한 줄 삽입이라 되돌리기 쉽다. 자료 구조 선택(라벨 유지 + 별도 지침 필드)은 `art_style_note` 선례를 따른 것이지 새 결정이 아니다.
- **완료 정의**: 시놉시스 화면에서 문체 지침을 저장·재조회할 수 있고, 지침이 있는 작품의 생성 프롬프트 4곳에 그 문장이 들어가며 **비어 있으면 아무것도 들어가지 않는다**. `task test`·`task lint`와 `pnpm typecheck`·`pnpm lint`·`pnpm test` 통과.

## 이 계획이 딛고 있는, 그릴링에서 확인한 사실

각 줄의 파일·행이 확인 수단이다.

1. **`work.style`은 `String(64)`이고 값은 3개뿐** — `works_models.py:41`, `genre-presets.schema.ts:4`의 `WRITING_STYLES = ['간결체','만연체','서정체']`. 작가 고유의 지침을 담을 자리가 없다.
2. **`style`이 주입되는 곳은 정확히 4곳** (`grep -rn "work.style" api/src`):
   - `chat_context_service.py:65` — 채팅
   - `assist/service/prompt_assembler.py:155`의 `_COMMON_BASE` — **집필 보조 8종 전부**(continue·infill·dialogue·style·correct·title·summary·draft)를 한 곳에서 커버한다
   - `manuscript_router.py:177` — 기획의도 이어쓰기
   - `works_router.py:161` — 비트 시트
3. **`art_style_note`가 대칭 선례** — `works_models.py:47`이 `Text()` nullable이고, 주석이 *"`style`(문체)과 헷갈리지 않게 `art_style_`로 접두한다"*고 밝힌다. `style_note`는 그 대칭이다.
4. **시놉시스 화면은 제목 + 기획의도만 담는다** — `synopsis-editor.tsx`. 기획의도는 blur 자동저장이 아니라 `저장`/`취소` 버튼으로 확정한다(파일 상단 주석과 63행). 문체 지침도 같은 방식을 따르면 일관된다.
5. **`_COMMON_BASE`는 `.format(genre=…, style=…)` 포맷 문자열** — `prompt_assembler.py:29-33, 155`. 인자를 늘리면 `tests/assist/test_prompt_assembler.py`가 잡는다.
6. **최신 마이그레이션은 `0006_work_art_style`** — `ls api/alembic/versions/`. 새 리비전은 `0007`이 된다.

## 작업 조각

- [ ] **S1. `style_note` 컬럼과 마이그레이션 `0007`** — `Work.style_note`를 `Text()` nullable로 추가한다. 완료 기준: 마이그레이션 왕복 테스트가 통과하고, **기존 작품이 `style_note IS NULL`로 남는 것**을 단언한다(ADR 260813-110724의 백필 금지). `alembic upgrade head` → `0007…(head)`. **왕복 테스트는 `api/CLAUDE.md`의 규약을 반드시 지킨다 — 복원을 `"head"`로 하고 `finally`에 둔다**(하드코딩 리비전이 공유 dev DB를 가둔 사고가 task 80에서 16 failed·150 errors를 냈다).
- [ ] **S2. 프롬프트 4곳에 조건부 주입** — 지침이 있을 때만 한 문장을 덧붙이고, 없으면 아무것도 넣지 않는다. 완료 기준: 4경로 각각에 대해 **(지침 있음 → 문장 포함) / (지침 없음·빈 문자열 → 미포함)** 두 방향을 테스트로 고정하고 통과. `_COMMON_BASE` 변경으로 집필 보조 8종이 한 번에 커버되는 것도 단언한다. (depends: S1)
- [ ] **S3. 시놉시스 화면의 문체 지침 섹션** — 기획의도 아래에 입력란과 `저장`/`취소`를 둔다(기획의도와 같은 확정 방식). 완료 기준: `pnpm typecheck`·`pnpm lint`·`pnpm test` 통과 + **브라우저에서 `/works/{workId}` 시놉시스 화면(좌측 내비 `시놉시스`, 1번째 항목)에 입력란이 보이고, 저장 후 새로고침해도 값이 남는 것**을 눈으로 확인. (depends: S2)

## 검증 노트 — 재발 가능한 함정

1. **마이그레이션 왕복 테스트의 복원 규약**(위 S1) — `api/CLAUDE.md`에 방금 승급된 규약이 이번 작업에 **바로 적용된다.** `downgrade`와 `upgrade` 사이에서 단정하는 형태도 같은 함정이다(단정이 실패하면 복원이 안 돈다).
2. **프롬프트 변경은 "문장이 들어간다"가 아니라 "빈 값일 때 안 들어간다"를 함께 봐야 한다.** 전자만 테스트하면 빈 지침이 `문체 지침: ` 같은 껍데기로 주입되는 것을 놓친다 — task 81의 프롬프트 마침표 겹침이 같은 종류의 미검출이었다.
3. **UI 변경은 jsdom이 못 보는 것이 있다** — 입력란의 존재는 RTL로 잡히지만 배치·폭은 브라우저에서만 확인된다(task 82의 레이아웃 교훈). S3의 육안 확인은 그래서 있다.
4. **브라우저 확인은 `aside-browser`로 한다** — 사용자 지시(2026-08-19). agent-browser MCP는 별도 프로필이라 로그인 세션이 없어 JWT 수동 주입이 필요하고, zustand persist가 덮어써 실패한다(task 82에서 실측).
5. **`task test`의 기존 무관 실패 12건을 새 결함으로 오인하지 말 것** — `Makefile` 부재에 의한 `TestMakefileHotReload` 9 + `TestMakeMigrate` 3이며, **errors 0**인지가 판단 기준이다. 그 밖에 `test_stream_cancel_shield` 4건이 간헐 실패한다(2026-08-20 관측, 타이밍 의존).
6. **미확인으로 남기는 것** — 문체 지침이 실제 생성 품질을 개선하는지는 이 계획이 검증하지 않는다. 프롬프트에 들어가는 것까지가 완료 기준이고, 문장 품질 판단은 작가의 몫이다.
