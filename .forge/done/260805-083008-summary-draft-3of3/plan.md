# 늘려쓰기 (3/3) — 요약으로 본문을 쓰고 화에 반영

## Goal / Non-goals
- Goal: 요약 모달에 **`늘려쓰기`** 버튼을 붙여, 편집란의 요약으로 화 본문을 생성해 에디터에 반영한다. ① 누르면 편집란 요약을 **먼저 저장**한다 ② 본문이 비어 있으면 그대로 넣고, **이미 원고가 있으면 대체 여부를 확인**한다 ③ 생성이 **끝난 뒤 한 번에** 반영한다.
- Non-goals: 백엔드 무변경(part 1/3의 `draft` 태스크를 소비만) · 요약 편집·저장 자체는 part 2/3 · 생성 중 실시간으로 에디터에 흘리지 않는다(아래 결정) · 커서 위치 삽입 옵션 없음 — 그 역할은 [[AI 이어쓰기]]가 이미 한다 · 여러 화 일괄 집필 없음 · 길이·톤 옵션 없음 · 생성 결과를 서버 `body`로 직접 PATCH하지 않는다(에디터에 넣고 기존 저장 경로에 맡긴다) · 새 ADR 없음.

## Source of truth
- Glossary: **늘려쓰기 (Draft from Summary)** — 이번 그릴링에서 신설. "[[AI 이어쓰기]]와 방향이 반대다 … 기존 원고를 지울 수 있고, 본문이 이미 있으면 대체 여부를 작가에게 확인해야 한다"가 이 파트의 계약이다. 이어쓰기 항목이 `_Avoid_`로 "AI가 원고를 대신 쓴다는 함의를 피한다"를 못박은 것과 정면으로 다르므로, UI·코드에서 두 낱말을 섞으면 안 된다.
- Related ADRs: 없음. **새 ADR 없음** — 되돌리기가 싸다(버튼 하나와 확인 다이얼로그).

### 착수 전 조사·실측으로 확정된 사실
- **`버전 기록`은 순전히 목업이다.** `Chapter.versions?`가 optional인데 `hydrate-chapters.ts`가 채우지 않고(grep 결과 `versions` 없음), 백엔드 `manuscript_models.py`에 버전 모델이 없고, `docs/data-model.md`에 버전 언급이 없고, `restoreChapterVersion`은 로컬 `set()`만 한다(`works.store.ts:307`). **즉 본문을 덮어쓰면 서버 쪽 복구 수단이 없다.** UI에 `버전 기록` 버튼이 있어 작가가 믿을 수 있다는 것이 이 사실의 위험한 부분이다.
- **에디터 undo/redo는 실재한다** — `manuscript.tsx:404,410`이 `editor.chain().focus().undo()/redo()`를 건다. 세션 내 되돌리기가 유일한 안전망이다.
- **화 이탈 자동 저장이 늘려쓴 본문을 저장한다 — 실측했다.** 실제 TipTap 에디터로 `editor.commands.setContent('<p>늘려쓴 본문</p>')`을 호출하니 **`onUpdate`가 발동**하고 그 콜백이 받은 텍스트가 `"늘려쓴 본문"`(에디터 실제 텍스트와 일치)이었다. 자동 저장은 `onUpdate`로 채우는 `latestBodyRef`를 읽으므로(`manuscript.tsx`), 늘려쓴 본문이 화 이탈 시 서버에 저장된다. **이걸 확인하지 않았다면 "본문이 화면엔 보이는데 화를 옮기면 사라진다"는 조용한 유실을 만들 수 있었다.** 같은 이유로 기존 `restoreVersion`도 안전하다.
- **확인 다이얼로그 관례가 있다** — `useModal`의 `openModal({ size, title, alert, txtCancel, handleOk })`. 화 삭제가 "복구할 수 없습니다" 문구로 쓴다(`work-tree.tsx:131`). 같은 결로 쓴다.
- **본문 반영 패턴이 있다** — `restoreVersion`이 `editor.commands.setContent(paragraphs.map(p => \`<p>${escapeHtml(p.text)}</p>\`).join(''))`을 쓴다(`manuscript.tsx:285-289`). 늘려쓰기도 같은 방식으로 넣는다(escape 누락은 XSS다).
- **`AssistTaskType`은 수동 동기화다** — 백엔드 `TaskType`에 태스크를 더해도 프론트 유니온·`AssistPayloadMap`을 손으로 맞춰야 하고, **테스트 목업이 타입을 우회해 `pnpm test`는 통과하고 `pnpm typecheck`만 잡는다**(task #68 divergence 2에서 실측).

### 결정 요약 (그릴링 합의)
- **본문이 비어 있으면 그대로 넣고, 이미 있으면 확인을 받는다.** 확인은 **대체/취소 2택**이다 — "커서 자리에 삽입"을 넣지 않는 이유는 그 역할이 이미 [[AI 이어쓰기]]에 있어서다. 늘려쓰기는 "요약 → 본문 생성", 이어쓰기는 "기존 본문 이어서"로 역할이 갈린다.
- **생성 완료 후 한 번에 반영한다.** 스트리밍으로 에디터에 직접 흘리면 중간에 취소했을 때 원고가 반쯤 지워진 상태로 남고 되돌리려면 undo를 여러 번 눌러야 한다. 일괄 반영이면 **undo 한 번**으로 복구된다 — 버전 기록이 목업인 상황에서 이게 유일한 안전망이므로 그 안전망을 최대한 단순하게 유지한다.
- **`늘려쓰기`는 편집란 요약을 먼저 저장한다.** 저장하지 않으면 본문만 남고 그 근거인 요약이 날아가 검토 화면이 비어 보인다 — "이 요약으로 이 본문을 만들었다"는 기록이 맞아떨어져야 한다.

## Definition of Done
- 요약 모달의 `늘려쓰기`를 누르면 편집란 요약이 저장되고, 그 요약으로 본문이 생성돼 에디터에 반영된다.
- **본문이 이미 있으면** 대체 확인을 거치며, 취소하면 생성도 하지 않는다(토큰도 쓰지 않는다).
- 반영 후 **되돌리기(⌘Z) 한 번**으로 이전 본문으로 돌아간다.
- 반영된 본문이 화를 떠날 때 자동 저장된다(실측한 `onUpdate` 경로).
- 편집란이 비어 있으면 늘려쓰기를 하지 않고 안내한다.
- web `pnpm typecheck` · `pnpm lint` · `pnpm test` 통과.

## 검증 노트 (직전 회고 반영)
- **UAT 경로와 레이블을 코드에서 인용한다**(#66 회고). 경로: **집필 화면(`/works/{workId}/write/{chapterId}`) 칩 줄의 `요약`** → 모달의 **`늘려쓰기`**. 칩 줄에는 `저장 · 요약 · 장면 이미지 · 다시쓰기 · 버전 기록`이 있으니 두 번째다. 확인 후 본문 반영은 사람이 확실히 볼 수 있는 항목이라 UAT로 맡기고, **되돌리기 한 번으로 복구되는지**도 UAT에 넣는다(이게 유일한 안전망이므로 눈으로 봐야 한다).
- **가장 그럴듯한 사고는 셋이다.** ① 스트림 전이 ref를 제목·요약과 공유해 **요약 생성이 끝났을 때 본문을 덮어쓰는 것** — 원고 유실이고 조용하다. 완성기준 S3-⑤로 못박았다. ② 확인 취소인데 생성이 이미 시작돼 토큰이 나가는 것 — S2-③. ③ 문단 HTML을 escape하지 않아 생성문의 `<` 가 마크업으로 먹히는 것 — S3-④. `restoreVersion`이 이미 `escapeHtml`을 쓰므로 그 패턴을 따른다.
- **`AssistTaskType` 누락은 테스트가 못 잡는다**(#68에서 실측: 315건 통과, typecheck만 잡음). S1의 완성기준 ①에 `pnpm typecheck`를 명시했다.
- **자동 저장이 늘려쓴 본문을 저장한다는 것을 계획 단계에서 실측했다** — `setContent`가 `onUpdate`를 쏘는 것을 실제 TipTap으로 확인했다(위 참조). "기존 방어 장치(자동 저장)가 있으니 괜찮다"고 넘기지 않은 이유는 #66 회고의 학습이다 — 방어가 있다는 것과 새 코드가 그 안에서 발동한다는 것은 다른 명제다.
