## 발산

1. **확인창 문구를 계획의 "이미 만든 N장은…"에서 "이미 만든 이미지는…"으로 바꿨다.** 작품 전체 이미지 수를 한 번에 주는 벌크 엔드포인트가 없고(그것을 만드는 것은 이 작업의 비목표), `hasAnyEntityImages()`가 `work.entities`의 각 카드에 병렬 요청을 보내 **존재 여부만** 판단한다. 정확한 총량 N을 얻으려면 요청이 더 늘어난다. 이 fan-out은 **화풍이 실제로 바뀌었을 때 저장 클릭 시점에만** 돌므로 화면 로드 비용은 0이다(마운트 시 미실행).
2. **화면을 `features/works/components`에 뒀다**(World Bible이 아니라). ADR이 [[작품 화풍]]을 "작품이 소유하는 첫 설정"이라 명명한 것과 맞고, `synopsis-editor.tsx`와 같은 결의 works 도메인 컴포넌트라는 판단.
3. **실제 폭에서 레이아웃이 허전하다 — 이 작업의 유일한 형태 문제다.** 화풍 카드가 콘텐츠 전체 폭을 쓰는데 견본 3장이 왼쪽에만 몰려 오른쪽이 크게 빈다(스크린샷 확인). 그릴링 목업은 좁은 카드에 52px 썸네일이었고 실제는 훨씬 넓다 — **jsdom이 관측할 수 없는 것**이라 계획이 "UAT에서 드러날 지점"으로 예고했던 그것이다. 기능 결함이 아니라 다듬을 여지이며, 견본을 키우거나 카드 폭을 제한하거나 4화풍을 2×2로 배치하는 안이 있다.
4. **S5가 409를 트러스트 바운더리 방어로 처리했다** — 화풍이 없으면 UI가 이미 생성 버튼을 숨기지만, 레이스 등으로 서버가 거부할 가능성에 대비해 `streamGenerateEntityImage`가 409 본문의 `detail`을 읽어 그 메시지로 throw한다. 계획이 요구한 것 이상이지만 옳은 방어다.
5. **테스트 순감을 정확히 대조했다.** 저장소 전체 380 → **394**(+14). 내역: `art-style-screen.test.tsx` +11(신규) · `work-shell.test.tsx` 1→2 **+1** · `entity-image-section.test.tsx` 10→12 **+2**. 합 +14로 관측치와 정확히 일치하며 **사라진 테스트는 없다**. (S2~S4 에이전트가 `work-shell.test.tsx`에 "2개 추가"라고 보고했으나 그 파일은 HEAD에 이미 1건이 있었고 최종 2건이므로 순증은 +1이다 — `git show HEAD:...`로 대조해 확인했다.)
6. **S5가 우려한 라우트 타입 에러는 없었다** — 다른 에이전트가 라우트 파일을 먼저 만들어 `routeTree.gen.ts`에 등록됐다(`grep -c "art-style"` → 13). 세션 중간에 보인 타입 에러 진단들은 병렬 편집 중의 낡은 스냅샷이었고, 최종 `pnpm typecheck`는 클린이다.

## 브라우저 UAT — 6단계 전부 통과

`:3001`(웹) + `:8000`(API). **사용자의 `:3000` 세션은 건드리지 않았다** — 3001은 다른 오리진이라 세션이 비어 있어 QA 계정을 주입해도 아무것도 침범하지 않는다.

1. 내비의 `이미지 스타일`(`Palette` 아이콘, 4번째) → 화풍 4개가 각각 **견본 3장**과 함께, **12장 전부 렌더·깨진 것 0**.
2. 현재 화풍 `수묵화`가 `aria-pressed=true`, 톤 입력에 저장값 `전체적으로 짙푸른 자톤, 종이 질감`.
3. 카드 상세 — **템플릿 그리드 0개**, `이 작품의 화풍` 한 줄, 설정 이미지 1장·대표·시각 묘사 유지.
4. 웹에서 `생성` → 새 이미지 생성. `template_id = ink-character`, **`is_primary = f`(두 번째가 대표를 바꾸지 않음)**, `final_prompt` 2050자가 **시각 묘사 → 작품 톤 → 화풍 조각 → 구도 조각** 순으로 끝난다. **눈으로 확인**: 수묵화 화풍·흰 배경·짙푸른 자톤·종이 질감이 모두 반영되고 이전 이미지와 같은 인물이다(시각 묘사 우선 규칙이 일관성을 만든 증거).
5. 화풍을 유화로 바꾸고 `저장` → 확인창 **"화풍을 바꿀까요? / 이미 만든 이미지는 그대로 남고, 앞으로 생성하는 이미지만 새 화풍을 따릅니다."** `취소` 클릭 후 **DB가 `ink` 그대로**.
6. 화풍 없는 작품(UAT용으로 만들고 끝나고 지웠다)의 카드 → `생성` 버튼 **없음** + 유도 문구.

## 실행 중 확인한 별개 사실 — `.test` 도메인 계정은 웹 로그인이 불가능하다

QA 계정으로 웹에 들어가려다 `/api/v1/auth/me`가 **500**을 내는 것을 관측했다. 원인은 pydantic `EmailStr`이 `.test`를 **예약 TLD로 거부**하는 것이고(`UserResponse.model_validate`에서 `ValidationError`), 이 저장소의 QA 잔여 계정 다수가 `@*.test`다. **실제 사용자 이메일에는 영향이 없어 제품 결함은 아니지만**, 그 계정들로는 브라우저 UAT를 할 수 없다. UAT를 위해 계정 하나의 이메일을 `qa-artstyle@example.com`으로 바꿨다(되돌리면 다시 못 쓰게 되므로 그대로 뒀다). **앞으로 QA 계정을 만들 때 `.test`를 쓰지 말 것.**
