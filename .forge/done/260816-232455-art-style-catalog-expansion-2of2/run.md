## 발산

1. **생성 경로를 게이트웨이에서 Codex `gpt-image-2`로 바꿨다 — 사용자 지시.** 원래 스크립트(`generate_template_samples.py`)로 30장을 돌렸으나 **10장만 성공하고 7장이 실패**한 뒤 레이트리밋 벽에 막혔다. 실패 양상이 셋이었고 **스크립트의 백오프는 429만 처리한다**:
   - 응답 지연 타임아웃 4건(`anime-character`·`watercolor-character`·`watercolor-location`·`concept-character`) — 재시도 없이 건너뜀
   - `503 Service Unavailable` 1건(`pen-character`) — 재시도 없이 건너뜀
   - **429 최종 실패 2건**(`render3d-character`·`render3d-location`) — 백오프 4단계(60·120·180·240초)를 다 소진하고 포기
   후반부에는 성공한 장도 백오프를 다 쓰고 **630초**가 걸렸다(`concept-item`). 남은 20장에 3시간을 태우고 0장을 얻을 위험이 있어 중단했고, 사용자가 `codex-image` 스킬(Codex CLI OAuth → 내장 `image_gen`, `gpt-image-2`)로 생성하라고 지시했다.
   - **결과: 20장 전부 성공, 실패 0건.** 5장씩 4배치로 `codex exec`를 순차 실행했다. 게이트웨이보다 훨씬 안정적이었다.
   - PNG로 나오므로 `sips -Z 320 ... -s format jpeg`로 기존 견본과 같은 규격(320px JPEG)으로 변환해 `samples/`에 넣고, 임시 디렉터리는 지웠다.
2. **모델이 섞였다 — 그리고 실제로는 문제가 되지 않았다.** 26장은 `antigravity/gemini-3.1-flash-image`, 20장은 `gpt-image-2`로 만들었다. 화면의 목적이 "같은 대상, 다른 화풍" 비교라 모델 차이가 화풍 차이를 오염시킬 수 있다고 **실행 전에 우려를 제기했고**, 완성 후 화면에서 확인한 결론은 **오염되지 않았다**는 것이다: gpt-image-2 쪽이 전반적으로 더 정교하고 인물이 크게 잡히지만, 대상(청색 무복 검객·안개 낀 산중 고찰·옥 장식 장검)이 일관돼 화풍 구분이 성립한다. **다만 이것은 육안 판단이며, 앞으로 견본을 부분 재생성할 때 모델이 더 섞이면 재검토가 필요하다.**
3. **계획의 검증 노트 3·4가 무의미해졌다.** `:3001` 오리진 격리와 `@*.test` 회피는 agent-browser MCP를 전제한 것인데, 사용자 지시로 `aside-browser`(사용자의 로그인된 브라우저)를 쓰게 되면서 격리 전략 자체가 적용되지 않았다. 확인은 **읽기 전용**으로 했다(클릭·저장 없음).
4. **엔드포인트 테스트를 계획보다 강하게 만들었다.** 계획은 목록을 14종으로 "넓히는" 것만 요구했으나, 이제 `test_art_style_sample_urls_return_200_jpeg`가 **화풍이 14종인지 단언하고 3유형 전부의 200 JPEG를 검사**한다. `event`는 애초에 화면이 요청하지 않으므로 검사 대상에서 뺐다.

## 후속 작업 후보

- **`수채화`의 아이템 견본이 74px 썸네일에서 거의 보이지 않는다.** 투명한 채색 + 완전한 흰 배경이 겹쳐 검이 사라진다. `애니메이션풍`·`펜화`의 아이템도 흐린 편이다. 겹침 문제가 아니라 **가시성** 문제이고 기능 결함이 아니라 이번에 임의로 바꾸지 않았다. 손보려면 아이템 구도 조각의 배경 지시(`완전한 흰 배경, 그림자 없음`)를 옅은 회색 배경으로 바꾸거나, 해당 화풍만 재생성한다.
- **생성 스크립트가 타임아웃·503에 재시도하지 않는다**(429만 재시도). 이번에 그 때문에 5장이 날아갔다. `generate_template_samples.py`의 `except` 절에 재시도를 넣을 후보다 — 다만 이제 Codex 경로가 더 안정적이라 스크립트 자체의 쓸모를 먼저 재검토할 일이다.
- **견본 생성 경로가 둘이 됐다** — 스크립트(게이트웨이)와 `codex-image`(gpt-image-2). 어느 쪽을 정본으로 삼을지 정하지 않았고, 스크립트 docstring은 여전히 게이트웨이만 기술한다.
- 프로젝트 `CLAUDE.md`의 "화면 확인 — agent-browser MCP" 문단이 사용자의 새 지시(aside-browser)와 어긋난다(part 1/2에서도 지적).
