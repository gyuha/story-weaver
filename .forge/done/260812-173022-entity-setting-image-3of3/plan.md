# 설정 이미지 (3/3): 웹 배선 — 템플릿 썸네일 선택 · SSE 진행 · 대표 이미지와 시각 묘사

## 목표 / 비목표

- 목표: 작가가 실제로 쓸 수 있게 만든다 — 카드 상세에 [[이미지 템플릿]] 썸네일 그리드와 생성 버튼을 두고, SSE 단계 진행·취소를 배선하고, [[대표 이미지]]를 크게 + 이력 썸네일 스트립으로 보여주고 대표를 바꾸게 하고, [[시각 묘사]]를 표시·편집하게 한다. 그리고 **목업을 철거한다** — `makePlaceholder()`와 로컬 전용 `imageUrl`이 사라진다.
- 비목표: 소설 본문에 이미지 적용(다음 ask). 개별 이미지 삭제 버튼. 이미지 확대·라이트박스. 드래그로 대표 변경. 백엔드 변경 일체(1/3·2/3에서 끝났다) — 스펙이 부족하면 3/3에서 고치지 말고 기록하고 멈춘다.

## 진실의 출처

- 글로서리 용어: **설정 이미지 · 이미지 템플릿 · 대표 이미지 · 시각 묘사** (`.forge/CONTEXT.md`). UI에 "에셋"이라는 말을 쓰지 않는다.
- 관련 ADR: `260811-234511`(생성이 18~60초라 SSE인 이유), `260811-234512`(**"같은 얼굴 보장"을 하지 못한다** — UI가 이것을 보장처럼 보이게 하면 안 된다는 제약), `260805-082723`(Base UI 모달 위에 겹치는 모달은 Base UI `Dialog`로만 — 확인창을 띄울 경우 적용).
- 기존 코드(전부 읽어 확인): `entity-detail.tsx:15-21`(`imageUrl`을 **58×58 아바타**로 이름 옆에 표시 — 큰 이미지 영역이 아니다), `entity-list.tsx:51-56`(18×18 썸네일), `entity-form.tsx:61-71`(mock 생성)·`273-300`(이미지 생성 섹션)·`325-332`(`makePlaceholder` + `escapeXml`), `entity-mapping.ts:17`·`works.store.ts:151,478-481`(`imageUrl`이 백엔드에 없어 로컬에만 병합).
- 화면 경로: World Bible은 `/works/$workId/bible`(`bible.index.tsx`), 편집은 `/works/$workId/bible/edit?entity=<id>`(`bible.edit.tsx`), 신규는 `/works/$workId/bible/new`(`bible.new.tsx`).
- **현재 UI 레이블(코드에서 인용)**: 섹션 제목 `이미지 생성`(`entity-form.tsx:275`), 버튼 `생성`(`:290`), 프롬프트 placeholder `이미지 프롬프트 (비우면 유형·이름·외모로 자동 구성)`(`:280`), 목업 토스트 `이미지를 생성했습니다 (목업)`(`:70`).
- Definition of Done: 카드 상세에서 템플릿을 썸네일로 골라 `생성`을 누르면 진행 단계가 보이고, 20~60초 뒤 대표 이미지가 크게 뜨고 [[시각 묘사]]가 채워지며, 다시 생성하면 스트립에 한 장 더 쌓이고 썸네일로 대표를 바꿀 수 있다. 새로고침해도 남아 있다(= 로컬 전용 `imageUrl`이 사라졌다는 증거). `makePlaceholder`가 저장소에 없다.

## 작업 조각

- [ ] S1. `pnpm generate` + 타입 배선 — completion criterion: 백엔드 OpenAPI에서 `src/api`를 재생성해 템플릿 카탈로그·이미지 목록·대표 지정·묘사 수정 훅이 생겼다. `src/api/**`는 손으로 고치지 않는다. `pnpm typecheck` 통과.

- [ ] S2. 이미지 섹션을 신규 폼에서 걷어내고 카드 상세로 옮긴다 — completion criterion: `entity-form.tsx`의 이미지 생성 섹션(`:273-300`)과 `makePlaceholder`/`escapeXml`(`:325-332`)·`generateImage`(`:64-71`)·`generatedImage` 상태·`onSubmit`의 `imageUrl`이 제거됐고, `grep -rn "makePlaceholder" web/src`가 0건이다. **`entity_images.entity_id`가 FK라 카드가 저장되기 전에는 이미지를 만들 수 없다** — 그래서 신규 폼에는 이미지 UI가 없고, 편집 폼에도 두지 않는다(생성은 카드 상세에서만). `works.store.ts:481`의 로컬 `imageUrl` 병합과 `:151`의 보존 로직도 함께 걷어낸다 — 서버가 진실의 출처가 되므로 존재 이유가 사라진다. 관련 테스트(`works.store.entities.test.ts:222` "백엔드에 없는 emoji/imageUrl/relations는 기존 로컬 값을 보존한다")를 **삭제가 아니라 갱신**한다. `pnpm test` 통과.

- [ ] S3. 템플릿 썸네일 그리드 선택 UI (TDD) — completion criterion: 카드 상세에 카드 유형에 맞는 템플릿만 썸네일 그리드로 뜨고, 하나를 고를 수 있으며, 선택 상태가 시각적으로 구분된다. 추가 지시 textarea는 유지한다(비우면 카드 필드로 자동 구성). 유형을 바꾼 카드에서 이전 유형의 템플릿이 남아 있지 않다 — `new-work-creation-wizard` 회고가 "동일 장르 재클릭 시 조용히 초기화"로 겪은 유형의 결함이므로 전이를 테스트로 고정한다. (depends: S1)

- [ ] S4. SSE 진행·취소 배선 (TDD) — completion criterion: `생성`을 누르면 단계 진행이 보이고(스트립에 "생성 중" 타일), `AbortController`로 중단할 수 있다. **취소해도 이미 만들어진 이미지는 목록에 남는다**(2/3의 계약). `assist.api.ts:175-180`의 `AbortController` 패턴을 따른다. **목을 만들 때 `stop()`의 부작용까지 재현한다** — `summary-draft` 회고가 `vi.fn()` 목이 `isStreaming: false` 전이를 만들지 않아 "테스트 초록 + 운영에서 덮어씀"을 낸 그 자리다. (depends: S1)

- [ ] S5. 대표 이미지 + 썸네일 스트립 + 대표 지정 (TDD) — completion criterion: 카드 상세에 대표 이미지가 **크게** 뜨고 그 아래 이력 썸네일 스트립이 있으며, 썸네일을 누르면 대표가 바뀌고 목록(`entity-list.tsx`의 18×18)과 상세 아바타(`entity-detail.tsx`의 58×58)에 즉시 반영된다. **`entity-detail.tsx`는 지금 이미지를 58×58 아바타로만 보여주므로 이것은 새 섹션 추가다**(스트립 한 줄 얹기가 아니다 — 그릴링 중 오판을 정정했다). 이미지가 0장인 카드는 기존 이모지 표시가 그대로다. (depends: S1)

- [ ] S6. 시각 묘사 표시·편집 (TDD) — completion criterion: 대표 이미지의 [[시각 묘사]]가 상세에 보이고 작가가 고칠 수 있으며, 저장하면 그 **이미지 행의** 묘사가 바뀐다(카드 `attributes`가 아니다 — ADR `260811-234512`). 묘사가 null인 이미지는 "이 이미지에는 묘사가 없습니다"로 드러나고 재생성 입력으로 쓰이지 않는다. **한글 입력 IME 가드**: 묘사 편집을 Enter/Backspace로 커밋하는 방식으로 만들지 않는다(별도 저장 버튼) — `new-work-creation-wizard` 회고가 "테스트 235건 초록인데 첫 입력부터 깨짐"을 낸 원인이고, 커밋 키를 쓸 경우 `isComposing` 가드가 필수다. (depends: S1)

- [ ] S7. 검증 — completion criterion: `cd web && pnpm typecheck` · `pnpm lint` · `pnpm test` 전부 통과. 그리고 **사람의 브라우저 UAT** — 아래 "UAT 지시" 절대로 진행한다. (depends: S1–S6)

## UAT 지시 (사람이 확인할 것 — 화면 경로와 레이블은 코드에서 인용)

`pnpm dev`(:3000) + 백엔드(:8000)를 띄운 뒤:

1. **`/works/<작품>/bible`** 로 가서 인물 카드 하나를 고른다.
2. 상세에 **템플릿 썸네일 그리드**가 있고, 썸네일이 실제 그림으로 렌더되는지 본다(깨진 이미지 아이콘이면 1/3의 샘플 서빙 문제다).
3. 템플릿 하나를 고르고 `생성`을 누른다 → **진행 표시가 뜨는지**, 20~60초 뒤 **대표 이미지가 크게 뜨는지**, [[시각 묘사]]가 채워지는지 본다.
4. **`생성`을 다시 누른다** → 스트립에 한 장 더 쌓이고 이전 장이 사라지지 않는지 본다(append-only).
5. 스트립의 다른 썸네일을 눌러 대표를 바꾼다 → 좌측 목록의 작은 썸네일과 이름 옆 아바타가 함께 바뀌는지 본다.
6. **새로고침한다** → 이미지와 묘사가 그대로 남아 있는지 본다. (목업 시절엔 여기서 사라졌다 — 이 한 단계가 "로컬 전용 `imageUrl` 철거"의 실질적 증거다.)
7. 장소·사건·아이템 카드에서 각각 템플릿 목록이 **그 유형용으로 바뀌는지** 본다.
8. **`/works/<작품>/bible/new`** 로 가서 이미지 생성 UI가 **없는지** 확인한다(카드 저장 전에는 만들 수 없다).

**브라우저로 관측하려 하지 말 것**: 취소 시 이미지 잔존(타이밍 의존 — S4의 테스트로 고정), 대표 지정의 낙관적 갱신 순서. 사람은 눈으로 확실히 보이는 것만 맡는다.

## 검증 노트 (이 플랜의 사실 주장은 어떻게 확인됐나)

**읽어서 확인한 것**:

- `entity-detail.tsx:15-21`이 **58×58 아바타**, `entity-list.tsx:51-56`이 **18×18** → 두 파일 해당 구간 읽음. **S5의 "새 섹션 추가"라는 판단의 근거이며, 그릴링 중 "이미 크게 보여준다"고 한 오판을 정정한 것이다.**
- `imageUrl`이 로컬 전용 → `grep -rn "imageUrl" web/src`(생성물 `src/api` 제외) 15건 확인. `entity-mapping.ts:17` 주석("emoji/imageUrl/relations는 백엔드에 없어 호출부가 보완한다")과 `works.store.ts:478` 주석이 명시. 백엔드 `Entity` 모델에 이미지 컬럼이 없음도 확인.
- 현재 UI 레이블 4개(`이미지 생성`·`생성`·프롬프트 placeholder·목업 토스트) → `entity-form.tsx` 해당 줄에서 그대로 인용.
- 화면 경로 → `ls web/src/routes/works/$workId/`로 `bible.index.tsx`·`bible.edit.tsx`·`bible.new.tsx` 확인. `bible.edit`가 `search: {entity}`를 쓴다는 것은 `entity-detail.tsx`의 `Link`에서 확인.
- `AbortController` 선례 → `assist.api.ts:175,180`.
- 영향받는 테스트 → `works.store.entities.test.ts:222,233,262`가 `imageUrl` 로컬 보존을 단정한다(3곳). **이것이 S2에서 갱신 대상인 전부인지는 `pnpm test`를 돌려 확인할 것** — grep으로 본 것이라 간접 참조를 놓칠 수 있다.

**아직 확인하지 않은 것 (실행 중 확인할 것)**:

- 카드 상세의 어느 위치에 이미지 섹션을 넣는 것이 [[타임라인 상태]] 목록과 충돌하지 않는지 — `entity-detail.tsx` 하단 구조를 읽고 결정한다.
- 브라우저에서 EventSource로 SSE를 받을 때 인증 토큰이 어떻게 실리는지. 이 저장소는 이미 `assist-sse-401-refresh`(2026-07-12 봉인)에서 이 문제를 다뤘으므로 **그 구현을 재사용한다** — 새로 만들지 않는다.
- 20~60초 대기 중 사용자가 다른 카드로 이동하면 무슨 일이 생기는지. `summary-draft` 회고가 "생성 중 이탈"에서 실제 사고를 냈으므로 S4에서 정한다.

**이 저장소가 반복한 함정 (회고에서 가져옴)**:

- **한글 입력은 자동 테스트에 보이지 않는다.** RTL `userEvent.type`은 composition 이벤트를 만들지 않고 Playwright도 IME를 우회한다 — `new-work-creation-wizard` 회고의 결론은 "도구 부족이 아니라 사람만 확인할 수 있는 종류"다. S6이 커밋 키를 쓰지 않는 것으로 이 함정을 **구조적으로 회피**한다.
- **jsdom이 관측할 수 없는 것을 테스트로 증명했다고 적지 말 것** — 페인팅·레이아웃·쌓임 순서·실제 크기. S5의 "크게 뜬다"는 사람이 봐야 한다(UAT 3번).
- **레이블 개칭을 파일 전체 치환하지 말 것.** `summary-draft` 회고가 `저장` → `요약 저장` 일괄 치환으로 테스트 6곳을 깨뜨렸다. S2에서 `생성`·`이미지 생성`을 건드릴 때 각 출현 위치의 `describe`를 먼저 확인한다.
- **UI 형태는 UAT에서 바뀐다는 것을 예상해 둘 것.** 같은 회고가 "UI 작업은 UAT 라운드를 형태 결정 단계로 계획하라"고 했다. **이번엔 그릴링 단계에서 fg-visual로 템플릿 선택 UI와 갤러리 레이아웃을 실제 화면으로 확정했다**(목업은 `.forge/visual/48950-1786458338/content/`에 남아 있다) — 그래도 남아 있을 형태 결정 지점은 **진행 표시의 위치**, **묘사 영역의 접힘 여부**, **생성 중 이탈 처리**다.
