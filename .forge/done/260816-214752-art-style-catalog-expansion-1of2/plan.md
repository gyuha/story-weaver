# 작품 화풍 카탈로그를 14종으로 늘리고 목록을 2열 그리드로 바꾼다

## 목표 / 하지 않을 것

- **목표**: `templates.json`의 화풍을 4종 → 14종으로 늘리고, 이미지 스타일 화면의 화풍 목록을 세로 스택에서 2열 그리드로 바꾼다. 견본 이미지는 이 계획에서 만들지 않는다(2/2가 맡는다).
- **하지 않을 것**:
  - 견본 썸네일 생성 — part 2/2. 이 계획이 끝난 시점에 새 화풍 10종은 🖼️ 플레이스홀더로 보인다(근거는 아래 "확인한 사실" 2번).
  - `event` 유형 견본 — 화면이 3유형만 렌더하므로 새 화풍에는 만들지 않는다(기존 4종의 `*-event.jpg` 4장은 그대로 둔다).
  - 기존 4종(`ink`·`webtoon`·`oil`·`photo`)의 `label`·`prompt_fragment` 수정.
  - 화풍의 그룹핑·카테고리 UI(장르형/기법형 구분 표시). 14개 평면 목록으로 간다.
  - `docs/image-generation.md` 갱신 — 이 문서가 옛 모델(화풍·구도 한 세트)을 기술한다는 지적이 #80·`work-art-style-2of2` 두 번 나왔으나 이번 작업의 범위가 아니다.

## 참조 근거

- **글로서리**: [[작품 화풍]] · [[이미지 템플릿]] · [[설정 이미지]] (`.forge/CONTEXT.md`). [[작품 화풍]] 정의에 박혀 있던 `(수묵화·웹툰·유화·사진풍 중 하나)`를 `(카탈로그가 제공하는 화풍 중 하나)`로 이번 그릴링에서 고쳤다 — 글로서리가 개수에 의존하지 않게.
- **관련 ADR**: `.forge/adr/260813-110724-work-owns-art-style-templates-own-composition.md` — 화풍은 작품이 갖고 구도는 템플릿이 갖는다. **이 ADR이 정한 규약을 지킨다: `style.prompt_fragment`는 매체·기법만 담는다**(`templates.json`의 `$comment`가 같은 말을 한다). 장르형 화풍(사이버펑크·다크 판타지 등)도 라벨만 장르를 연상시키고 프롬프트는 기법으로 쓴다 — 톤·분위기는 화면의 `작품 고유의 톤` 입력란이 갖는 축이라 겹치면 안 된다.
- **새 ADR 없음** — JSON 항목 추가라 되돌리기 쉽고, 위 규약은 기존 ADR의 적용일 뿐 새 결정이 아니다.
- **완료 정의**: `templates.json`의 `styles`가 14개이고, `GET /api/v1/art-styles`가 14건을 돌려주며, 이미지 스타일 화면이 14개를 2열 그리드로 렌더한다. `task test`·`task lint`와 `pnpm typecheck`·`pnpm lint`·`pnpm test`가 전부 통과한다.

## 이 계획이 딛고 있는, 그릴링에서 실제로 확인한 사실

각 줄 끝의 괄호가 확인 수단이다. **확인하지 않은 것은 아래 "검증 노트"에 미확인으로 남겼다.**

1. **화면 코드는 화풍 개수에 의존하지 않는다** — `art-style-screen.tsx:79`가 `artStyles.map(...)`으로 API 목록을 그대로 돈다. 카탈로그만 늘리면 개수는 따라온다. (파일 전문 열람)
2. **견본 파일이 없어도 화면은 깨지지 않는다** — 파일이 없으면 라우터가 404(`image_generation_router.py:270-271`), `SampleThumbnail`의 `onError`(`art-style-screen.tsx:160`)가 `broken`으로 전환해 150행의 🖼️ 플레이스홀더를 그린다. **이 경로에는 직전 실행이 방어 제거 red를 확인한 테스트가 이미 있다**(`work-art-style-2of2` run.md의 "견본 `onError` 대체 제거 → 견본 404 red"). (두 파일 해당 행 열람 + 직전 run.md)
3. **`event` 견본은 어디에도 표시되지 않는다** — 백엔드는 4유형 URL을 다 내보내지만(`image_generation_router.py:251-259`가 `list_compositions()`를 돌아 4건), 프론트는 `SAMPLE_TYPES` 3개만 렌더한다(`art-style-screen.tsx:14-18`). 프론트 테스트가 `수묵화 사건 견본`의 부재를 단언한다(`art-style-screen.test.tsx:149`). (grep + 파일 열람)
4. **4종을 고정하는 백엔드 테스트는 두 곳** — `test_art_style_endpoints.py:87-89`(`len(body) == 4`, `ids == {"ink","webtoon","oil","photo"}`)와 `test_template_catalog.py:27`(`STYLE_IDS`). (`grep -rn` over `api/tests/`)
5. **프론트 테스트는 자체 mock 4건을 쓰므로 카탈로그 확장의 영향을 받지 않는다** — `art-style-screen.test.tsx:74-105`가 화풍 4건을 직접 만들어 주입한다. (파일 열람)
6. **2열이 폭에 들어간다** — 컨테이너는 `max-w-[820px]`(`art-style-screen.tsx:72`), 썸네일은 `h-16 w-20` = 64×80px(161행), 견본 3장 + `gap-2`(8px)×2 = 256px, 카드 `p-3`(12px)×2 = 24px → 카드 하나에 **280px**이면 충분하다. 2열이면 카드당 ~400px이므로 여유가 있다. **단 이것은 클래스 값을 읽은 산술이지 렌더 실측이 아니다 — S3의 브라우저 확인이 진짜 증거다.**

## 확정된 화풍 14종

기존 4종은 그대로 두고 아래 10종을 `styles` 배열에 순서대로 덧붙인다. `id`에 하이픈을 쓰지 않는다 — 견본 파일명이 `<style>-<type>.jpg`(`template_catalog.py:75`)라 구분자와 섞이지 않게 한다.

| id | label | prompt_fragment |
|---|---|---|
| `anime` | 애니메이션풍 | 일본 애니메이션 작화, 부드러운 그러데이션 채색과 간결한 윤곽선 |
| `shoujo` | 소녀만화풍 | 소녀만화 일러스트, 파스텔 톤 채색과 섬세한 선 |
| `watercolor` | 수채화 | 수채화, 번지는 물감과 투명한 채색 |
| `pen` | 펜화 | 흑백 펜 드로잉, 촘촘한 해칭과 굵은 윤곽선 |
| `concept` | 콘셉트 아트 | 디지털 콘셉트 아트, 정교한 디테일과 극적인 조명 |
| `render3d` | 3D 렌더 | 3D 시네마틱 렌더, 물리 기반 재질과 얕은 피사계 심도 |

| `oriental` | 동양 채색화 | 동양 진채 채색화, 광물 안료의 선명한 색과 금선 묘사 |
| `cyberpunk` | 사이버펑크 | 네온 조명 디지털 페인팅, 청보라 림라이트와 하이테크 질감 |

## 검증 노트 — 이 영역의 직전 실행이 남긴 함정

`work-art-style-1of2`·`2of2`의 run.md/STATUS.md에서 읽은 것들이다.

1. **이 작업의 S3는 직전 실행이 열어둔 미결 항목이다.** `2of2`의 발산 3: *"화풍 카드가 콘텐츠 전체 폭을 쓰는데 견본 3장이 왼쪽에만 몰려 오른쪽이 크게 빈다 … 다듬는 방법 셋: 견본을 키우거나 · 카드 폭을 제한하거나 · 4화풍을 2×2로 배치. **사람이 보고 정할 일이라 이번에 임의로 바꾸지 않았다.**"* 이번 그릴링에서 사람이 2열 그리드를 골랐다. 즉 S3는 새 아이디어가 아니라 **닫는 작업**이다.
2. **레이아웃은 jsdom이 볼 수 없다 — 클래스 문자열을 단언하는 테스트를 만들지 말 것.** 직전 실행이 정확히 이 함정에 걸렸다(목업은 52px 썸네일의 좁은 카드, 실제는 훨씬 넓은 폭이라 UAT에서야 허전함이 드러났다). 같은 이유로 `zIndex` 단언 테스트가 목표를 증명하지 못한 사례가 task #71에 있다. **S3의 검증은 브라우저 육안 확인이며, TDD on이지만 이 조각만 예외다.** 그 대신 S3는 기존 11건의 테스트를 깨지 않는 것으로 회귀를 막는다.
