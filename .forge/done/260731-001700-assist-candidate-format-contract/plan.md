# 이어쓰기 후보를 JSONL로 받기 — 형식 계약 + 4계층 관용 파서

## Goal / Non-goals
- Goal: 이어쓰기 후보의 출력 형식이 **암묵적 계약**이라 모델이 형식을 표류시키면 이어쓰기가 고장 나는 문제를 근본에서 고친다. ① 백엔드 `continue_` 프롬프트에 **후보 하나 = JSON 객체 한 줄**(`{"text":"후보 본문"}`, JSONL) 지시를 명시 ② web 파서를 JSONL 기준으로 교체하고 **4계층 관용**을 둔다 — JSONL 줄 → 코드펜스 벗긴 단일 JSON(`candidates` 배열) → 줄 시작 라벨(`N.`/`N)`·`**후보 N**`·`### 후보 N`) → 원문 1개 폴백 ③ **"하나씩 로딩" 연출을 유지**한다(#60·#61의 산출물).
- Non-goals: **`response_format={"type":"json_object"}`을 쓰지 않음** — 이 엔드포인트가 지원함을 실측했으나 응답 전체가 단일 JSON 객체여야 해서 **스트리밍 중 증분 파싱이 불가능**하고, 그러면 #60·#61이 만들어 UAT까지 통과한 "하나씩 로딩"을 잃는다 · **다른 assist 태스크 무변경**(`style`·`correct`·`infill`·`dialogue`·`title`) — 전부 단일 본문 반환이라 JSON으로 감싸 얻을 이익이 없고, 이 모델에서 머리말 없이 깨끗함을 실측했다 · `dynamic_update`의 기존 JSON 경로 무변경 · 후보 개수 `3~5개`를 고정 개수로 바꾸지 않음 · **`---` 구분자를 지시하지 않음**(JSONL로 대체되었고, 관용 목록에도 넣지 않는다 — 우리가 지시했을 때만 나온 형식이라 실측된 실패 모드가 아니다) · 백엔드에서 응답을 파싱·정규화해 구조화된 SSE로 내려주지 않음(와이어 포맷 무변경) · `parsePartialSuggestions` 호출부 시그니처 무변경 · LLM 설정(`.env`) 무변경 · 일반 마크다운 장식(`**강조**`·`## 소제목`)이나 인라인 라벨을 후보 경계로 받지 않음

## Source of truth
- Glossary terms: **AI 이어쓰기 (Continue)** in `.forge/CONTEXT.md` — "작가가 후보를 채택한다"는 정의가 근거다. 후보를 **고를 수 있게** 분리하는 것이 파서의 존재 이유이고, 형식이 깨지면 후보 여러 개가 한 덩어리로 뭉쳐 "채택" 자체가 성립하지 않는다. 형식·스키마는 구현 세부이므로 글로서리에 넣지 않는다.
- Related ADRs: `0012-ai-chapter-title-as-assist-task.md`(assist 태스크 구조와 `title_`의 출력 형식 못박기 선례) · `0002-hybrid-memory-architecture.md`(프롬프트에 주입되는 메모리 컨텍스트). **새 ADR 없음** — 프롬프트 한 문장 + 파서 한 함수라 되돌리기가 싸고 3조건 게이트를 통과하지 못한다.
- 착수 전 측정·확인으로 확정된 사실:
  - **근본 원인**: `prompt_assembler.py:36-39`의 `continue_` 지시는 `"다음 문장 3~5개 후보를 생성하세요"`뿐이고 **출력 형식을 지정하지 않는다.** web 파서(`parse-suggestions.ts`의 `MARKER = /(?:^|\n)\s*\d+[.)]\s*/g`)는 모델이 우연히 내던 `1.` 번호를 계약으로 삼았다.
  - **표류를 DB 로그로 정량화했다(`llm_call_logs`, `task='assist.continue'`)**:

    | 모델 | 총 | `N.` 번호 | `**후보 N**` | `### 후보 N` |
    | --- | --- | --- | --- | --- |
    | `openai/glm-4.6` (구 z.ai) | 6 | **6** | 0 | 0 |
    | `openai/codex/gpt-5.6-sol-low` | 3 | 0 | 2 | 1 |
    | `openai/cx/gpt-5.6-terra` (현재) | 10 | 6 | **4** | 0 |

    z.ai가 6/6으로 번호를 냈기 때문에 파서가 "동작하는 것처럼" 보였을 뿐이다(운). 현재 모델은 같은 프롬프트로 **같은 분 안에** `1.`과 `**후보 N**`을 섞어 내며 **10회 중 4회(40%) 고장**이다.
  - **표류는 계약이 없을 때만 일어난다** — 형식을 명시하면 준수한다. `---` 구분자 지시 4/4 준수, **JSONL 지시 4/4 준수**(140청크 스트리밍 → 4줄, 4줄 전부 유효 JSON + `text` 키). 2026-07-30 실측.
  - **`response_format={"type":"json_object"}`은 이 엔드포인트에서 동작한다** — `{"candidates":[...]}`를 정상 반환했다. 그러나 응답 전체가 하나의 JSON 객체여야 해서 스트리밍 중 부분 파싱이 불가능하다(`{"candidates":["가","나` 는 유효 JSON이 아님). 그래서 채택하지 않는다.
  - **JSONL이 구분자보다 구조적으로 안전하다** — 후보 본문의 개행은 JSON 문자열 안에서 `\n`으로 이스케이프되므로 **줄 경계와 절대 충돌하지 않는다**. `---`나 번호는 본문에 같은 패턴이 나오면 오분할 위험이 남는다.
  - **라벨은 항상 줄 시작에 온다 — 로그 원문으로 확인**: 저장된 응답은 `**후보 1**` + 개행 + 본문 구조다(대화에 붙여진 샘플이 한 줄로 보인 것은 복사 시 개행이 접힌 것). 번호 형식도 `1.` 뒤에 개행이 오는 변형이 있다. ⇒ **줄 시작 앵커로 충분하고 인라인 매칭의 오분할 위험을 감수할 필요가 없다.**
  - **코드펜스는 실측된 실패 모드다** — `extraction_service.py:63-70`이 이미 `_CODE_FENCE_RE`로 ` ```json ` 펜스를 벗겨낸다("일부 모델(GLM-4.6 등)은 순수 JSON 대신 마크다운 코드펜스로 감싸 응답한다"). JSON을 요구하면 이 모드가 재현될 것을 전제해야 한다.
  - **다른 태스크는 이번 모델에서도 깨끗하다** — `style`(다시쓰기)·`correct`(교정)를 실제 프롬프트로 호출해 머리말·라벨 없이 본문만 나오는 것을 확인했다.
  - **파서 소비자 전수 확인**(트리 전체 grep): `parsePartialSuggestions`는 `suggestion-picker.tsx:30`(팝오버 — 소비자 2곳이 공유: `selection-ai-menu.tsx`, `synopsis-editor.tsx`)과 `:98`(모달)에서만 호출된다. `parseSuggestions`는 **운영 호출부가 없고** `parsePartialSuggestions` 내부와 자기 테스트에서만 쓰인다. → `parseSuggestions` 내부 로직만 교체하면 소비자 코드는 무변경.
  - **기존 테스트가 구 계약을 곁쇄한다**: `parse-suggestions.test.ts`의 번호 기반 케이스(`parseSuggestions('1. 가\n2. 나\n3. 다')` → `['가','나','다']` 등)는 새 계약에서 **관용 계층 ③으로만** 성립한다. 통과시키려 번호 로직을 1급 계약으로 남기는 것이 가장 그럴듯한 실패 경로다.
- 결정 요약(그릴링 합의):
  - **형식 = JSONL.** 한 줄에 후보 하나, `{"text":"후보 본문"}`. 스키마를 객체로 둔 이유: 측정에서 이 형태로 4/4 준수했고, 나중에 필드를 늘릴 여지가 있으며, `text` 키 존재로 유효성을 판정할 수 있다.
  - **4계층 관용.** 각 계층이 실측된 실패 모드에 대응하므로 speculative가 아니다: ① JSONL 줄(지시 형식) ② 코드펜스로 감싼 단일 JSON(`extraction_service` 선례) ③ 줄 시작 라벨(로그 40% 실측) ④ 원문 1개(최후).
  - **증분 파싱은 JSONL 계층에서 성립한다** — 스트리밍 중에는 **개행이 도착해 완결된 줄**만 후보로 확정하고 마지막 줄은 자라는 중으로 본다(스켈레톤 1개). 스트리밍 중 JSONL이 하나도 안 잡히면 스켈레톤만 보이고, 완료 시 ②③④ 폴백이 작동해 후보가 뜬다. 구현 방법은 실행 단계가 정한다.
  - **`response_format` 미채택**(위 비목표) — 보장은 강하지만 "하나씩 로딩"과 교환할 수 없다.
- Definition of Done:
  - 이어쓰기(집필 화면 `AI 이어쓰기`, 선택 영역 `늘리기`) 실행 시 후보가 **개별 카드로 분리**되어 뜨고, 스트리밍 중 완성된 후보가 **하나씩** 채워지며 맨 아래 스켈레톤 1개가 남는다(브라우저 육안, **최소 5회 반복**).
  - `적용`을 누르면 **JSON 껍데기(`{"text":`)나 라벨이 원고에 섞이지 않고** 그 후보 본문만 삽입된다.
  - 모델이 JSONL을 어긴 응답(코드펜스·라벨·형식 없음)에서도 깨지지 않고 후보가 뜬다.
  - `style` 경로(다시쓰기·줄이기·톤 변경)는 여전히 후보 1개로 정상 표시된다(회귀 없음).
  - api `task lint`·`task test`, web `pnpm typecheck`·`pnpm lint`·`pnpm test` 통과.

## 검증 노트 (직전 회고 반영)
- **소비자를 트리 전체에서 grep해 확정했다** — #61은 파일 두 개만 grep하고 "확인했다"고 플랜에 써서 세 번째 소비자(`synopsis-editor.tsx`)를 놓쳤다. 이번엔 전수 결과를 위에 적었다.
- **구 계약을 곁쇄하는 테스트를 미리 지목했다** — 번호 기반 케이스는 이제 관용 계층 ③이며 1급 계약이 아니다.
- **테스트 green을 검증 증거로 쓰지 않는다** — 후보가 실제로 카드로 분리되어 보이는지, JSON 껍데기가 원고에 섞이지 않는지는 브라우저 육안 UAT가 필수다. 이 문제 자체가 "테스트는 다 통과하는데 실사용이 깨진 상태"로 발견됐다.
- **UAT는 확률적 고장을 상대한다** — 형식 표류가 확률적으로 나오므로 이어쓰기를 **최소 5회** 실행해야 한다. 한 번 성공을 통과로 기록하면 안 된다(내가 샘플 하나로 "이 모델은 정상"이라 단정해 틀린 전례가 이 작업의 출발점이다).
- **프롬프트 문구·파서 구현 방법은 실행 단계가 정한다** — 플랜은 "JSONL 지시가 포함되고 다른 태스크에는 새지 않는다", "완결된 줄만 후보로 확정한다" 같은 관찰 가능한 결과만 못박는다(retro `260727-000846` 교훈 ①).
- **모델 전환은 이미 적용돼 있다** — `llm_call_logs`가 `openai/cx/gpt-5.6-terra` 호출을 기록하므로 서버는 재시작된 상태다. 프롬프트 변경은 `--reload-dir src`가 잡으므로 추가 재시작이 필요 없다.
