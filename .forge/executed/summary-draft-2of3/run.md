## 계획대로 된 것

- **TDD 규율을 지켰다.** S1은 `../summary-modal` 모듈의 새 계약이 없어(모듈 해석 실패 후 6건 red), S2·S3는 편집란 값 불일치 3건으로 red를 먼저 봤다.
- **`done` 단계가 사라졌다.** 계획대로 "생성 결과가 편집란에 들어오고 `저장`이 확인 역할을 한다"로 합쳐져, `phase`가 `idle | generating` 둘로 줄었다. 직전 작업(#—)에서 만든 4단계가 3단계 → 2단계로 단순해졌는데, **확인 없이 덮어쓰지 않는다는 계약은 유지**된다(`닫기`는 저장하지 않음).
- **계획이 지목한 두 함정을 둘 다 테스트로 막았다.** ① 저장 페이로드에 `body` 동봉 금지 — 스토어·컴포넌트 양쪽에서 단정 ② 편집란 초기화 타이밍 — 저장된 요약이 바뀔 때(다른 화로 이동/생성 결과 도착) 새 값으로 맞춰지는지 `rerender`로 단정, 에러가 와도 편집 내용을 건드리지 않는지 단정.
  - **`body` 동봉 방어가 실재하는지 재확인했다** — `saveChapterSummary`가 `body`를 함께 싣도록 임시 변경하니 스토어 테스트 red(1 failed / 12 passed), 복원 후 13 passed.
- **비목표 무침범** — `늘려쓰기` 버튼 자리도 만들지 않음 · 백엔드 무변경 · 글자 수 표시 없음 · 요약 편집 이력 없음 · 검토 화면 편집 없음 · 자동 저장 없음 · 새 ADR 없음.

## 계획과 달라진 것 (divergence)

1. **생성 결과를 별도 prop 대신 `existingSummary`로 흘려보냈다.** 계획 S2는 "결과를 편집란 값으로 넣는다"만 적었고 방법을 열어 뒀다. 모달이 이미 `existingSummary`가 바뀔 때 편집란을 재동기화하므로, 부모가 `summaryDraft` 상태를 들고 `existingSummary={summaryDraft ?? chapter.summary}`로 내려보내면 새 배선이 필요 없다. `generatedText` prop이 사라져 모달 계약이 하나 줄었다.
2. **`onApply` → `onSave`로 이름이 바뀌고 모달을 닫지 않는다.** 계획 S3의 "저장 후 모달은 열린 채로" 결정을 반영했다 — 연달아 손보는 흐름을 끊지 않는다.
3. **생성 중에는 편집란을 `sr-only`로 감추고 스켈레톤을 대신 보여준다.** 계획은 "편집란이 비활성"만 적었는데, 비활성 편집란과 스켈레톤을 동시에 쌓으면 모달이 두 배로 길어진다. 접근성 트리에는 남겨(테스트가 `disabled`를 단정) 시각적으로만 교체했다.
4. **`lint:fix`가 1파일 정리**(테스트의 긴 JSX 줄).
